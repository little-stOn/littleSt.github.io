## 为什么选择 ARM？

本教程通常面向想要学习 ARM 汇编基础知识的人，特别是那些对在 ARM 平台上编写漏洞利用程序感兴趣的读者。你可能已经注意到，**ARM 处理器在你周围无处不在**。环顾四周时，我家里配备 ARM 处理器的设备远多于配备 Intel 处理器的设备。这包括手机、路由器，还有近年来销量暴增的物联网（IoT）设备。可以说，ARM 处理器已成为全球最普及的 CPU 核心之一。这也带来了一个事实：就像个人电脑一样，物联网设备也容易受到不当输入验证滥用的影响，例如缓冲区溢出。鉴于基于 ARM 设备的广泛使用及其被滥用的可能性，针对这些设备的攻击变得越来越普遍。

然而，专门研究 x86 安全的专家要比研究 ARM 的专家多得多，尽管 ARM 汇编语言可能是目前广泛使用的汇编语言中最容易上手的一种。那么，为什么没有更多的人关注 ARM 呢？也许是因为外面涵盖 Intel 漏洞利用的学习资源比 ARM 的多。想一想由 Fuzzy Security 或 Corelan Team 编写的优秀 Intel x86 漏洞利用教程——诸如此类的指南帮助了对这一特定领域感兴趣的人获得实践知识，并激发他们学习教程以外的内容。如果你对 x86 漏洞利用开发感兴趣，Corelan 和 Fuzzysec 的教程将是你完美的起点。而在本教程系列中，我们将专注于 ARM 汇编基础与漏洞利用编写。

## ARM 处理器 vs. Intel 处理器

Intel 和 ARM 之间存在许多差异，但主要区别在于指令集。Intel 是 CISC（复杂指令集计算）处理器，具有更大且功能更丰富的指令集，允许通过许多复杂的指令访问内存。因此，它具有更多的操作和寻址模式，但寄存器数量少于 ARM。CISC 处理器主要用于普通的 PC、工作站和服务器。

**ARM 是 RISC（精简指令集计算）处理器**，因此拥有简化的指令集（通常在100条指令以内）以及比 CISC 更多的通用寄存器。与 Intel 不同，**ARM 使用仅对寄存器进行操作的指令，并在内存访问上使用加载/存储（Load/Store）内存模型**，这意味着只有加载/存储指令才能访问内存。也就是说，如果要在一台 ARM 设备的特定内存地址上将一个 32 位值递增，需要三种类型的指令（加载、递增和存储）：首先将特定地址处的值加载到寄存器中，在寄存器内对其进行递增，最后将其从寄存器存回内存。

精简指令集有其优点和缺点。**优点之一是可以更快地执行指令**，从而有可能提高速度（RISC 系统通过减少每条指令的时钟周期（CPI）来缩短执行时间）。**缺点是指令更少**，这意味着在可用的有限指令下，对高效编写软件提出了更高的要求。还需要注意的是，ARM 具有两种模式：ARM 模式和 Thumb 模式。Thumb 指令可以是 2 字节或 4 字节（更多内容请参见第 3 部分：ARM 指令集）。

ARM 与 x86 之间的其他差异包括：

* 在 ARM 中，大多数指令都可用于条件执行（Conditional Execution）。
* Intel x86 和 x86-64 系列处理器使用小端（Little-Endian）格式。
* 在 ARMv3 之前，ARM 架构是小端格式的。从那时起，ARM 处理器变为双端（Bi-Endian）架构，并提供了一项允许切换字节序的设置。

不仅 Intel 和 ARM 之间存在差异，甚至在不同的 ARM 版本之间也存在差异。本教程系列旨在尽可能保持通用性，让你了解 ARM 的整体工作原理。一旦你了解了基础知识，就很容易掌握你所选择的特定目标 ARM 版本的细微差别。本教程中的示例是在 32 位 ARMv6（Raspberry Pi 1）上创建的，因此相关解释均针对该确切版本。

不同 ARM 版本的命名可能会令人困惑：

| ARM 家族 (ARM Family) | ARM 架构 (ARM Architecture) |
| --- | --- |
| ARM7 | ARM v4 |
| ARM9 | ARM v5 |
| ARM11 | ARM v6 |
| Cortex-A | ARM v7-A |
| Cortex-R | ARM v7-R |
| Cortex-M | ARM v7-M |

## 编写汇编

在深入研究 ARM 漏洞利用开发之前，我们需要先了解汇编语言编程的基础知识，这需要你掌握一些背景知识才能体会它的魅力。但是，为什么我们非得需要 ARM 汇编不可？用一种“普通”的编程/脚本语言来编写我们的漏洞利用程序还不够吗？如果我们想要进行逆向工程（Reverse Engineering）并理解 ARM 二进制文件的程序执行流、构建我们自己的 ARM shellcode、制作 ARM ROP 链以及调试 ARM 应用程序，那确实是不够的。

你不必了解汇编语言的每一个微小细节才能进行逆向工程和漏洞利用开发，但为了理解全局，掌握其中的一些是必须的。本教程系列将涵盖这些基础知识。如果你想了解更多，可以访问本章末尾列出的链接。

那么，汇编语言到底是什么？汇编语言只是机器码之上的一层很薄的语法层。机器码由指令组成，这些指令被编码为二进制表示形式，这也是计算机唯一能懂的语言。那么为什么我们不直接写机器码呢？好吧，那将是非常痛苦的。因此，我们将编写汇编代码——即 ARM 汇编，它对人类来说要容易理解得多。我们的计算机自身无法直接运行汇编代码，因为它需要机器码。我们将使用的、将汇编代码转换为机器码的工具是 GNU Binutils 项目中名为 `as` 的 GNU 汇编器，它用于处理具有 `*.s` 扩展名的源文件。

一旦你编写好后缀为 `*.s` 的汇编文件，你需要用 `as` 进行汇编并用 `ld` 进行链接：

```bash
$ as program.s -o program.o
$ ld program.o -o program
```

## 汇编底层揭秘 (Assembly under the hood)
让我们从最底层开始，逐步向上了解汇编语言。在最底层，我们在电路上只有电信号。信号是通过将电压切换到两个电平之一来形成的，例如 0 伏（“关/off”）或 5 伏（“开/on”）。因为仅凭肉眼我们无法轻易分辨电路此时所处的电压，我们选择使用视觉表示法——即数字 0 和 1，写下开/关电压的模式。这不仅是为了表达是否存在信号的概念，也是因为 0 和 1 本就是二进制系统的数字。然后，我们将一系列的 0 和 1 组合成机器码指令，这是计算机处理器最小的工作单元。下面是一个机器语言指令的例子：

```text
1110 0001 1010 0000 0010 0000 0000 0001
```

到这里一切都好，但我们无法记住这些（0和1构成的）模式各自代表什么。出于这个原因，我们使用所谓的“助记符（mnemonics）”——帮助我们记住这些二进制模式的缩写，并为每个机器码指令指定一个名称。这些助记符通常由三个字母组成，但这并不是强制的。我们可以使用这些助记符作为指令来编写一个程序。这个程序就叫做汇编语言程序（Assembly Language Program），而代表该计算机机器码的这一套助记符集合就被称为该计算机的汇编语言（Assembly Language）。因此，汇编语言是人类用于为计算机编程的最底层语言。指令的操作数紧跟在助记符之后。下面是一个例子：


```asm
MOV R2, R1
```


既然我们已经知道汇编程序是由被称为助记符的文本信息组成的，我们就需要将它转换为机器码。正如上面提到的，在 ARM 汇编的情况下，GNU Binutils 项目为我们提供了一个叫做 `as` 的工具。使用像 `as` 这样的汇编器将（ARM）汇编语言转换为（ARM）机器码的过程称为“汇编（assembling）”。
总而言之，我们了解到计算机能够理解（响应）电压（信号）的存在与否，并且我们可以将多个信号用 0 和 1 的序列（位/bits）来表示。我们可以使用机器码（信号序列）让计算机以某些明确定义的方式作出响应。由于我们记不住这些长长的序列都意味着什么，我们给了它们缩写——也就是助记符，并用它们来代表指令。这套助记符集合就是该计算机的汇编语言。同时我们使用一个叫作汇编器（Assembler）的程序将代码从助记符表示形式转换成计算机可读的机器码，这就和编译器为高级编程语言所做的工作一样。
