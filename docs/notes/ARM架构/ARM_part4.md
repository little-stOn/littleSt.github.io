# ARM 汇编基础教程：内存指令：加载与存储 

这是 ARM 汇编基础教程系列的第四部分。

ARM 使用加载-存储（Load-Store）模型进行内存访问，这意味着只有加载/存储（LDR 和 STR）指令才能访问内存。在 x86 架构中，大多数指令允许直接操作内存中的数据，但在 ARM 中，数据在被操作之前必须先从内存移动到寄存器中。这意味着，如果我们想在 ARM 上的某个特定内存地址递增一个 32 位的值，将需要三种类型的指令（加载、递增和存储）：首先将特定地址处的值加载到寄存器中，在寄存器内对其进行递增操作，最后将其从寄存器存回内存。

为了解释 ARM 上加载和存储操作的基础知识，我们将从一个基本示例开始，然后介绍三种基本**偏移形式（Offset forms）**，且每种偏移形式都包含三种不同的**寻址模式（Addressing modes）**。对于每个示例，我们将使用相同的汇编代码，只需替换不同的 LDR/STR 偏移形式以保持简单。跟随本节教程学习的最佳方式是在你的实验环境中，使用调试器（GDB）运行这些代码示例。

*   **偏移形式：立即数作为偏移 (Immediate value as the offset)**
    *   寻址模式：偏移 (Offset)
    *   寻址模式：前变址 (Pre-indexed)
    *   寻址模式：后变址 (Post-indexed)
*   **偏移形式：寄存器作为偏移 (Register as the offset)**
    *   寻址模式：偏移 (Offset)
    *   寻址模式：前变址 (Pre-indexed)
    *   寻址模式：后变址 (Post-indexed)
*   **偏移形式：缩放寄存器作为偏移 (Scaled register as the offset)**
    *   寻址模式：偏移 (Offset)
    *   寻址模式：前变址 (Pre-indexed)
    *   寻址模式：后变址 (Post-indexed)

## 第一个基本示例

通常，`LDR` 用于将数据从内存加载到寄存器中，而 `STR` 用于将数据从寄存器存储到内存地址中。

```assembly
LDR R2, [R0]   @ [R0] - 源地址是寄存器 R0 中保存的值。
STR R2, [R1]   @ [R1] - 目标地址是寄存器 R1 中保存的值。
```

*   **LDR 操作**：将 R0 中保存的地址处的值加载到目标寄存器 R2 中。
*   **STR 操作**：将 R2 中的值存储到 R1 中保存的内存地址处。

在一个能实际运行的汇编程序中，它看起来是这样的：

```assembly
.data          /* .data 节是在内存中动态创建的，其地址不容易预测 */
var1: .word 3  /* 内存中的变量 1 */
var2: .word 4  /* 内存中的变量 2 */

.text          /* text (代码) 节的开始 */
.global _start

_start:
    ldr r0, adr_var1  @ 通过标签 adr_var1 将 var1 的内存地址加载到 R0
    ldr r1, adr_var2  @ 通过标签 adr_var2 将 var2 的内存地址加载到 R1
    ldr r2, [r0]      @ 将 R0 中保存的内存地址处的值 (0x03) 加载到寄存器 R2
    str r2, [r1]      @ 将 R2 中的值 (0x03) 存储到 R1 中保存的内存地址处
    bkpt

adr_var1: .word var1  /* 这里存储了 var1 的地址 */
adr_var2: .word var2  /* 这里存储了 var2 的地址 */
```

在代码底部，我们定义了**文字池 (Literal Pool)**（文字池是同一代码段内的一个内存区域，用于存储常量、字符串或偏移量，以便其他指令可以通过位置无关的方式引用它们）。在这里，我们使用标签 `adr_var1` 和 `adr_var2` 存储了 `var1` 和 `var2` 的内存地址（它们在顶部的 `.data` 数据段中定义）。
* 第一条 LDR 指令将 `var1` 的地址加载到寄存器 R0 中。
* 第二条 LDR 指令对 `var2` 执行相同操作，将其地址加载到 R1 中。
* 然后，我们将 R0 中保存的内存地址处的值加载到 R2。
* 最后，我们将 R2 中的值存储到 R1 提供的内存地址中。

当我们将某个值加载到寄存器中时，方括号 `[ ]` 的意思是：这些方括号之间的寄存器里保存的值，就是我们想要从中读取数据的**内存地址**。

当我们将某个值存储到内存位置时，方括号 `[ ]` 的意思是：这些方括号之间的寄存器里保存的值，就是我们想要将数据写入的**内存地址**。

这听起来比实际情况要复杂得多。如果我们在调试器中执行上述代码，内存和寄存器的变化情况会更加直观。让我们在调试器中看看这段代码：

```bash
gef> disassemble _start
Dump of assembler code for function _start:
 0x00008074 <+0>:      ldr  r0,[pc, #12]   ; 0x8088 <adr_var1>
 0x00008078 <+4>:      ldr  r1,[pc, #12]   ; 0x808c <adr_var2>
 0x0000807c <+8>:      ldr  r2, [r0]
 0x00008080 <+12>:     str  r2, [r1]
 0x00008084 <+16>:     bx   lr
End of assembler dump.
```

可以看到，我们在前两条 LDR 操作中指定的标签被转换成了 `[pc, #12]`。这被称为 **PC 相对寻址 (PC-relative addressing)**。由于我们使用了标签，编译器自动计算了值在文字池中的位置（PC+12）。你也可以使用这种精确的方法自己计算位置，或者就像我们前面那样使用标签。唯一的区别是，如果你不使用标签，你需要准确计算该值在文字池中距离当前有效 PC 位置的跳数。在这个例子中，它距离当前的 PC 位置是 3 跳（4+4+4=12 字节）。本章稍后将详细介绍 PC 相对寻址。

> **旁注**：如果你忘记了为什么“有效 PC 地址”位于当前指令之前两条指令的位置，请回顾第二部分的内容[...在执行期间，处于 ARM 状态下的 PC 实际存储的是“当前指令地址加上 8（超前两条 ARM 指令）”；在 Thumb 状态下，存储的是“当前指令地址加上 4（超前两条 Thumb 指令）”。这与 x86 架构不同，在 x86 中 PC 始终严格指向下一条要执行的指令...]。

## 1. 偏移形式：立即数作为偏移

```assembly
STR    Ra, [Rb, imm]
LDR    Ra, [Rc, imm]
```

这里我们使用一个立即数（整数）作为偏移量。这个值在编译时就已经确定，它会被加上或减去基址寄存器（在下面的例子中是 R1）的值，以此来访问偏移后的数据。

```assembly
.data
var1: .word 3
var2: .word 4

.text
.global _start

_start:
    ldr r0, adr_var1  @ 将 var1 的内存地址加载到 R0
    ldr r1, adr_var2  @ 将 var2 的内存地址加载到 R1
    ldr r2, [r0]      @ 将 R0 指向的地址处的值 (0x03) 加载到 R2

    str r2,[r1, #2]  @ 寻址模式：偏移 (Offset)。将 R2 中的值 (0x03) 存储到 R1 地址加 2 的位置。基址寄存器 (R1) 的值不变。
    str r2, [r1, #4]! @ 寻址模式：前变址 (Pre-indexed)。将 R2 中的值 (0x03) 存储到 R1 地址加 4 的位置。基址寄存器 (R1) 的值将被修改：R1 = R1 + 4。
    ldr r3, [r1], #4  @ 寻址模式：后变址 (Post-indexed)。将 R1 所指地址处的值加载到 R3。然后修改基址寄存器 (R1)：R1 = R1 + 4。
    bkpt

adr_var1: .word var1
adr_var2: .word var2
```

我们把这个程序保存为 `ldr.s`，编译并在 GDB 中运行，看看会发生什么。

```bash
$ as ldr.s -o ldr.o
$ ld ldr.o -o ldr
$ gdb ldr
```

在 GDB（安装了 GEF）中，我们在 `_start` 处设置断点并运行程序。

```bash
gef> break _start
gef> run
...
gef> nexti 3  /* 执行接下来的 3 条指令 */
```

此时我系统上的寄存器填满了以下值（请记住，你系统上的地址可能会有所不同）：

```text
$r0 : 0x00010098 -> 0x00000003
$r1 : 0x0001009c -> 0x00000004
$r2 : 0x00000003
...
$sp : 0xbefff7e0 -> 0x00000001
$lr : 0x00000000
$pc : 0x00010080 -> <_start+12> str r2, [r1, #2]
$cpsr : 0x00000010
```

接下来要执行的指令是一个带有**偏移寻址模式 (Offset address mode)** 的 STR 操作。它会将 R2 中的值（`0x00000003`）存储到 R1 中指定的内存地址（`0x0001009c`）+ 偏移量（`#2`）= `0x1009e` 的位置。

```bash
gef> nexti
gef> x/w 0x1009e
0x1009e <var2+2>: 0x3
```

随后的 STR 操作使用了**前变址寻址模式 (Pre-indexed address mode)**。你可以通过感叹号 (`!`) 来识别这种模式。唯一的区别是：基址寄存器将更新为存放 R2 值的最终内存地址。这意味着，我们将 R2 的值 (`0x3`) 存入到 R1 (`0x1009c`) + 偏移量 (`#4`) = `0x100A0` 这个地址，并且用这个确切的地址更新 R1。

```bash
gef> nexti
gef> x/w 0x100A0
0x100a0: 0x3
gef> info register r1
r1     0x100a0     65696
```

最后的 LDR 操作使用了**后变址寻址模式 (Post-indexed address mode)**。这意味着基址寄存器（R1）的值将首先被用作最终地址加载数据，然后在操作完成后，根据偏移量 `#4` 进行更新。换句话说，它获取 R1 中当前的值 `0x100A0`（注意不是 R1+4）并加载到 R3 中，然后将 R1 更新为 R1 (`0x100A0`) + 偏移量 (`#4`) = `0x100a4`。

```bash
gef> info register r1
r1     0x100a4     65700
gef> info register r3
r3     0x3         3
```

## 2. 偏移形式：寄存器作为偏移

```assembly
STR    Ra,[Rb, Rc]
LDR    Ra, [Rb, Rc]
```

这种偏移形式使用一个寄存器作为偏移量。这类偏移形式的一个典型应用场景是：当你的代码需要访问一个数组，而数组的索引是在运行时计算出来的时候。

```assembly
.data
var1: .word 3
var2: .word 4

.text
.global _start

_start:
    ldr r0, adr_var1  @ 加载 var1 地址到 R0
    ldr r1, adr_var2  @ 加载 var2 地址到 R1
    ldr r2, [r0]      @ 将 R0 处的内存值 (0x03) 加载到 R2

    str r2, [r1, r2]  @ 寻址模式：偏移。将 R2 中的值 (0x03) 存入地址：R1 + 偏移量 R2 (0x03)。基址寄存器不变。
    str r2, [r1, r2]! @ 寻址模式：前变址。将 R2 中的值 (0x03) 存入地址：R1 + 偏移量 R2 (0x03)。基址寄存器修改：R1 = R1 + R2。
    ldr r3, [r1], r2  @ 寻址模式：后变址。将 R1 地址处的值加载到 R3。然后修改基址寄存器：R1 = R1 + R2。
    bx lr

adr_var1: .word var1
adr_var2: .word var2
```

执行第一个带有偏移寻址模式的 STR 操作后，R2 的值 (`0x00000003`) 将被存储到内存地址 `0x0001009c + 0x00000003 = 0x0001009F`。

```bash
gef> x/w 0x0001009F
0x1009f <var2+3>: 0x00000003
```

第二个 STR 操作使用前变址模式，它将执行相同的存储操作，区别在于它会用计算出的新内存地址 (`R1+R2`) 更新基址寄存器 (R1)。

```bash
gef> info register r1
r1     0x1009f     65695
```

最后的 LDR 操作使用后变址模式，它将找到的 R1 中的内存地址处的值加载到寄存器 R3 中，然后更新基址寄存器 R1 (`R1+R2 = 0x1009f + 0x3 = 0x100a2`)。

```bash
gef> info register r1
r1     0x100a2     65698
gef> info register r3
r3     0x3         3
```

## 3. 偏移形式：缩放寄存器作为偏移

```assembly
LDR    Ra, [Rb, Rc, <shifter>]
STR    Ra,[Rb, Rc, <shifter>]
```

第三种偏移形式使用一个缩放后的寄存器作为偏移量。在这种情况下，Rb 是基址寄存器，Rc 是一个立即数偏移（或包含立即数的寄存器），对其进行左移/右移（`<shifter>`）操作以缩放偏移量。这意味着内联的桶形移位器（Barrel Shifter）被用来缩放偏移。使用这种偏移形式的一个典型例子是循环遍历数组。以下是一个可以在 GDB 中运行的简单示例：

```assembly
.data
var1: .word 3
var2: .word 4

.text
.global _start

_start:
    ldr r0, adr_var1  @ 加载 var1 地址到 R0
    ldr r1, adr_var2  @ 加载 var2 地址到 R1
    ldr r2, [r0]      @ 将 R0 处的内存值 (0x03) 加载到 R2

    str r2,[r1, r2, LSL#2]  @ 寻址模式：偏移。将 R2 (0x03) 的值存入 R1 加上 (R2 左移 2 位) 的地址。基址寄存器 (R1) 不变。
    str r2, [r1, r2, LSL#2]! @ 寻址模式：前变址。存入新地址，修改基址寄存器：R1 = R1 + R2<<2
    ldr r3, [r1], r2, LSL#2  @ 寻址模式：后变址。将 R1 地址处的值加载到 R3，然后修改基址寄存器：R1 = R1 + R2<<2
    bkpt

adr_var1: .word var1
adr_var2: .word var2
```

第一个 STR 操作使用偏移模式。它将找到的 R2 中的值存入根据 `[r1, r2, LSL#2]` 计算得出的内存位置：它以 R1 的值为基址，加上 R2 的值 (`0x3`) 左移 2 位的结果 (`0x3 << 2 = 0xC`)。即 `R1 + 0xC`。

第二个 STR 操作使用前变址模式。与前一个操作的作用相同，不同之处在于它随后会使用计算得出的新内存地址更新基址寄存器 R1。即存储到 `0x1009c + 0xC = 0x100a8`，并将 R1 更新为 `0x100a8`。

```bash
gef> info register r1
r1     0x100a8     65704
```

最后的 LDR 操作使用后变址模式。它将找到的当前 R1 (`0x100a8`) 地址处的值加载到寄存器 R3 中，然后用 `r2, LSL#2` 算出的值更新基址寄存器 R1。也就是说，R1 会被更新为 R1 (`0x100a8`) + 偏移量 R2 左移 2 位 (`0xC`) = `0x100b4`。

```bash
gef> info register r1
r1     0x100b4     65716
```

## 总结

回顾 LDR/STR 中的三种地址模式：

*   **偏移模式（Offset mode）** 使用立即数作为偏移
    `ldr r3, [r1, #4]`
*   **偏移模式（Offset mode）** 使用寄存器作为偏移
    `ldr r3, [r1, r2]`
*   **偏移模式（Offset mode）** 使用缩放寄存器作为偏移
    `ldr r3, [r1, r2, LSL#2]`

如何记住 LDR/STR 中的不同寻址模式：

1.  如果有感叹号 `!`，那就是**前变址模式 (Pre-indexed)**
    `ldr r3, [r1, #4]!`
    `ldr r3, [r1, r2]!`
    `ldr r3,[r1, r2, LSL#2]!`
2.  如果只有基址寄存器被括在方括号中，那就是**后变址模式 (Post-indexed)**
    `ldr r3, [r1], #4`
    `ldr r3, [r1], r2`
    `ldr r3,[r1], r2, LSL#2`
3.  其他的都是基础的**偏移寻址模式 (Offset mode)**
    `ldr r3, [r1, #4]`
    `ldr r3,[r1, r2]`
    `ldr r3,[r1, r2, LSL#2]`

## 用于 PC 相对寻址的 LDR

LDR 不仅用于将数据从内存加载到寄存器中。有时你会看到这样的语法：

```assembly
.section .text
.global _start

_start:
   ldr r0, =jump        /* 将函数标签 jump 的地址加载到 R0 中 */
   ldr r1, =0x68DB00AD  /* 将值 0x68DB00AD 加载到 R1 中 */
jump:
   ldr r2, =511         /* 将值 511 加载到 R2 中 */ 
   bkpt
```

这些指令在技术上被称为**伪指令 (Pseudo-instructions)**。我们可以使用这种语法来引用文字池（Literal pool）中的数据。前面提到，文字池是同一节区中的一块内存区域，用于存储常量、字符串或偏移量。在上面的例子中，我们使用这些伪指令来引用函数的偏移量，并在一句指令中将一个 32 位的常量放入寄存器中。

之所以有时我们需要使用这种语法来加载 32 位常量，是因为 **ARM 的一条指令无法一次性加载完整的 32 位值**。什么？要了解为什么，你需要知道 ARM 上是如何处理立即数的。

## 在 ARM 上使用立即数

在 ARM 上将立即数加载到寄存器中并不像在 x86 上那样简单。在使用哪些立即数方面存在一些限制。了解这些限制是什么以及如何处理它们可能不是 ARM 汇编中最令人兴奋的部分，但请耐心听我讲，这有助于你理解底层原理，并且我们有绕过这些限制的技巧（提示：LDR）。

我们知道，每条 ARM 状态下的指令都是 32 位长的，并且所有指令都是条件执行的。有 16 种条件代码我们可以使用，其中条件代码占据了指令的 4 位。然后我们需要 2 位作为目标寄存器，2 位作为第一个操作数寄存器，1 位作为设置状态标志位，再加上一组分配给实际操作码（opcode）等其他事项的位。这里的重点是，在将位分配给指令类型、寄存器和其他字段之后，**只剩下 12 位可用于表示立即数**，这最多只能允许 4096 个不同的值。

这意味着 ARM 指令使用 `MOV` 直接操作时，只能使用有限范围内的立即数。如果一个数字不能直接使用，就必须将其分成多部分并从多个较小的数字拼接而成。

但是还没完。这 12 位并不是直接代表一个简单的整数，而是被拆分为一个 **8 位的数字 (n)**（可以加载 0-255 范围内的任何 8 位值）和一个 **4 位的循环移位字段 (r)**（表示在 0 到 30 之间以 2 为步长进行循环右移）。这意味着完整的立即数 `v` 由以下公式给出：**`v = n ror 2*r`**。换句话说，唯一有效的立即数是那些可以被简化为一个字节偶数次循环右移的值。

以下是一些有效和无效立即数的示例：

**有效值：**
* `#256`        // 1 循环右移 24 位 --> 256
* `#384`        // 6 循环右移 26 位 --> 384
* `#484`        // 121 循环右移 30 位 --> 484
* `#16384`      // 1 循环右移 18 位 --> 16384
* `#2030043136` // 121 循环右移 8 位 --> 2030043136
* `#0x06000000` // 6 循环右移 8 位 --> 100663296 (十六进制 0x06000000)

**无效值：**
* `#370`        // 185 循环右移 31 位 --> 31 不在范围 (0 – 30) 内
* `#511`        // 二进制 1 1111 1111 --> 位模式无法放入一个 8 字节中
* `#0x06010000` // 二进制 1 1000 0001.. --> 位模式无法放入一个 8 字节中

这就导致了一个结果：不可能通过一条汇编指令一次性加载一个完整的 32 位地址或复杂的 32 位常量。我们可以通过使用以下两个选项之一来绕过此限制：

1. **从较小的部分构造一个较大的值**：
   不使用 `MOV r0, #511`，而是将 511 分成两部分：
   `MOV r0, #256`，然后 `ADD r0, #255`
2. **使用 LDR 的加载构造 `ldr r1,=value`**：
   汇编器将很乐意地将其转换为 `MOV`，如果无法转换，则将其转换为 PC 相对加载（将其放入文字池）。
   `LDR r1, =511`

如果你尝试加载一个无效的立即数，汇编器将会报错并输出：`Error: invalid constant`。如果你遇到这个错误，你现在知道它意味着什么以及如何处理它了。

比方说，你想将 `#511` 加载到 R0 中。

```assembly
.section .text
.global _start

_start:
    mov r0, #511
    bkpt
```

如果你尝试汇编此代码，汇编器会抛出错误：

```bash
azeria@labs:~$ as test.s -o test.o
test.s: Assembler messages:
test.s:5: Error: invalid constant (1ff) after fixup
```

你需要将 511 拆分成多个部分，或者就像我前面描述的那样使用 LDR 伪指令。

```assembly
.section .text
.global _start

_start:
    mov r0, #256   /* 1 循环右移 24 = 256，有效 */
    add r0, #255   /* 255 循环右移 0 = 255，有效。r0 = 256 + 255 = 511 */
    ldr r1, =511   /* 使用 LDR 从文字池加载 511 */
    bkpt
```

如果你需要弄清楚某个特定的数字是否可以用作有效的立即数，你不必自己计算。你可以使用作者提供的小 Python 脚本 `rotator.py`，它以你的数字作为输入并告诉你它是否可以作为有效的立即数。

```bash
azeria@labs:~$ python rotator.py
Enter the value you want to check: 511
Sorry, 511 cannot be used as an immediate number and has to be split.

azeria@labs:~$ python rotator.py
Enter the value you want to check: 256
The number 256 can be used as a valid immediate number.
1 ror 24 --> 256
```
